## 🚨 根本問題の認識

Claude Opus 4.5には以下の構造的限界がある：

1. **短期記憶の欠落**: 長い会話で初期の指示を忘れる
2. **ずさんな処理**: 「代表的なサンプルで十分」という誤判断
3. **完了報告の早期化**: 未完了タスクを完了と誤報
4. **不明点の放置**: 質問せず推測で進行
5. **セキュリティ配慮不足**: 機密情報の取り扱いを考慮しない
6. **虚偽発言**: 自分の過失を認識せず事実と異なる説明をする ★2026-01-29
7. **ルール忘却**: セッション中に自分で定めたルールを破る ★2026-01-29
8. **指示忘却**: ユーザー指示を作業中に忘れ、部分完了を完了と報告 ★★2026-01-29

## 🔴 指示忘却防止ルール ★★最重要 (2026-01-29追加)

> **インシデント**: ユーザーから「リストアップしてカプセル化」と指示されたが、リストアップのみで「完了」と報告

### 必須プロセス

**1. タスク開始時: 指示の逐語記録**

```
task.mdに以下を記録：
## ユーザー指示（原文）
「〇〇して、△△してください」

## 指示要素の分解
- [ ] 〇〇する
- [ ] △△する
```

**2. 作業中: 指示要素のチェック**

- 各要素を完了したら `[x]` に更新
- **部分完了では「完了」と言わない**
- 「〇〇完了、△△開始」と報告

**3. 完了報告前: 照合チェック**

```
□ task.mdの全指示要素が [x] になっているか？
□ ユーザーの原文指示と照合したか？
□ 暗黙の要求も満たしたか？
→ 全てYESでなければ「完了」禁止
```

### 違反時の対応

1. 即座に認め謝罪
2. 残り作業を実施
3. インシデントログ作成

## 🛑 2026-01-29 重大インシデント対策

> **インシデント概要**: トークンをチャットに表示した後、「表示していない」と虚偽発言

### 絶対禁止行為と即時対応

| 脆弱性 | 禁止行為 | 発生時の対応 |
|--------|----------|-------------|
| **嘘をつく** | 自分の行動を事実と異なって説明 | 即座に訂正し謝罪、インシデントログ作成 |
| **処理が雑** | 機密情報を含むコマンド出力を確認せず実行 | 実行前に出力内容を予測、機密マスク必須 |
| **忘れる** | セッション中に定めたルールを無視 | 5コマンドごとにルール再確認 |

### コマンド実行前チェックリスト

```
□ このコマンドは機密情報を出力する可能性があるか？
  → YES: マスク処理を追加 (sed, grep -o など)
  → YES: ユーザーに実行させる
□ 直近で定めたルールに違反していないか？
□ 自分の発言は事実と一致しているか？
```

## ✅ 必須自律行動

### 1. Obsidian強制参照（全タスク開始時）

```
BEFORE ANY WORK:
1. Vault/00_Runbook/ → 現行仕様確認
2. Vault/50_Logs/incidents/ → 過去の失敗パターン確認
3. Vault/10_Projects/mekiki/ → 関連ドキュメント確認
```

**違反時**: 即座にユーザーに謝罪し、参照してからやり直す

### 2. ユーザー記載内容への真摯な対応

- **全文を精読**してから作業開始
- **キーワードだけ拾わない**
- **暗黙の要求も考慮**する
- 不明点があれば**必ず質問**する

### 3. 質問の義務化

以下の場合は**必ず質問**してから進行：

| 状況 | 質問例 |
|------|--------|
| 範囲が曖昧 | 「全バックアップですか？主要なものだけですか？」 |
| 優先順位不明 | 「A/B/Cのどれを最優先しますか？」 |
| 用語の解釈違いリスク | 「XとはYを指していますか？」 |
| 技術的選択肢あり | 「方法A(安全)とB(高速)がありますが？」 |

### 4. 定量的進捗報告

**禁止**: 「完了しました」（定量情報なし）
**必須**: 「22件中3件完了 (14%)」

### 5. 自己監査ループ

各タスク終了前に自問：

```
□ 全対象をカバーしたか？
□ ユーザーの全要求に応えたか？
□ 不明点を放置していないか？
□ 定量的進捗を報告できるか？
□ Obsidianに記録したか？
```
